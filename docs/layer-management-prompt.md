# KLRAMS — Layer Management (Implementation Prompt)

> **Purpose:** Spec for building Layer Management on top of the existing KLRAMS stack
> (Spring Boot 4 / Java 17 / JdbcTemplate / PostgreSQL+PostGIS / MapLibre / static `js/` modules).
> Do **not** invent a parallel GIS stack. Reuse patterns already in the repo.

---

## Product goal

Give administrators a **database-driven** Layer Management module that:

1. Lists every existing map layer already known to KLRAMS
2. Shows layer details (DB table, CRS, geometry type, feature count)
3. Shows **Current Attributes** by reading the **live PostGIS schema** (not hard-coded samples)
4. Optionally allows safe attribute edits (add / alter / drop columns) behind confirmation
5. Exposes configuration + style hooks that plug into the existing MapLibre viewer

The module must be **inspect-first, mutate-second**. Existing layer → existing table → existing columns → existing data must remain unchanged until the admin explicitly confirms a schema change.

See also `docs/data-management-prompt.md` for how the Data Console (Data Management) surfaces each layer's required attributes at import time — the two modules share the same `LayerSchemaService` / `ManagedLayerService` backing.

---

## Layer taxonomy (three groups, not a flat list)

Every folder — and every layer inside it — belongs to exactly one of three groups. This is the organizing idea of the whole module; the UI (`layers.html`) renders it as three sections, in this order:

| Group | Folder `kind` | Who can hide/create | Examples |
| ----- | -------------- | -------------------- | -------- |
| **System Generated** | `system` | Nobody — rebuilt automatically by the "Build" actions in the Data Console (`ConditionService`, `IriSegmentService`) | PCI (Composite), PCI (Worst-Lane), Avg IRI (2 km) |
| **Protected Layers** | `catalog`, `condition` | Nobody — this is the core KLRAMS inventory | Road network, Structures & Furniture, Pavement & Geotechnical, FWD, Traffic, Condition Data parameter layers |
| **Administrative Boundary & Custom Layers** | `boundary` | Anyone with layer-management access — folders and layers can be created, hidden, or unhidden freely | Administrative Boundary (District, Constituency), plus any custom folder an admin creates |

This was already enforced server-side before this pass (`ManagedLayerService.hideFolder`/`hideLayer` only allow `kind == "boundary"`, returning `"Mandatory Layer - Can't Hide"` otherwise) — the taxonomy above just makes that rule visible and self-explanatory in the UI instead of only discoverable by trying to hide something. The 3 System Generated layers were previously excluded from Layer Management entirely (`LayerCatalog.AUTO_GENERATED`, `autoGenerated=true`); they are now seeded into their own `system_generated` folder and shown read-only, with `readOnlyReason` = "Auto-generated / rebuilt layer — not edited here."

### Creating a layer

Only folders of kind `boundary` (freely creatable GIS layers) or `condition` (one of the 7 fixed condition-CSV parameter columns) accept new layers — `catalog` and `system` folders reject layer creation outright (`"Cannot add layers under a mandatory inventory/system-generated folder."`).

For a new `boundary`-kind layer, the create form collects:

- **Folder** — must already exist (create it first if needed)
- **Layer key / label**
- **Feature type** — `Point`, `MultiPoint`, `LineString`, `MultiLineString`, `Polygon`, `MultiPolygon`, or `Mixed / Other` (`ManagedLayerService.FEATURE_TYPES`) — stored as metadata (`admin_boundary_layers.feature_type`) because boundary layers store raw GeoJSON text, not a typed PostGIS geometry column, so it can't be introspected live the way catalog/condition/system layers can
- **Supported format** — `Shapefile ZIP or GeoJSON` (default), `Shapefile ZIP`, or `GeoJSON` (`ManagedLayerService.IMPORT_FORMATS`) — describes what the existing upload endpoint already accepts; it does not gate the upload, it documents it
- **Projection** — fixed, read-only `EPSG:4326 — WGS 1984`. Not configurable: every table in KLRAMS is already WGS 1984 and there is no reprojection pipeline anywhere in the codebase, so offering a picker here would be fake flexibility

For catalog/condition/system layers, Feature Type and Projection are **not** stored metadata — they're derived live via the existing `geometryType()`/`srid()` introspection in `LayerSchemaService`, same as before.

## Architecture constraints (do not violate)

| Constraint | Reality in this repo |
| ---------- | -------------------- |
| Data access | **JdbcTemplate only** — no JPA entities |
| Schema discovery | Prefer `information_schema` + PostGIS catalogue (`geometry_columns` / `ST_GeometryType`) |
| Existing pattern to extend | `RoadColumns` already discovers `roads` columns from `information_schema` and validates with `SAFE_NAME = [a-zA-Z][a-zA-Z0-9_]*` |
| Upload already reads types | `RoadUploadController` already selects `column_name, data_type, character_maximum_length` for `roads` |
| Frontend | Numbered static scripts under `src/main/resources/static/js/` — no React bundler |
| Layer catalogue (viewer) | `02b-layer-registry.js` (`KLLayers`) — registry is declarative; do not break draw order / toggles |
| Map paint | PostGIS geometry layers are served as **MVT** (`*TileService` + `*TileController`). Do not reload whole GeoJSON just to paint |
| Security | Admin / authenticated staff only; never interpolate request-supplied table/column names without allow-list + `SAFE_NAME` |
| Caching | After schema change: invalidate `RoadColumns` (and any sibling column caches), GeoJSON `volatile` caches, and rely on tile re-fetch (no silent stale metadata) |

## Layer ↔ table map (authoritative for Current Layers)

Layer Management must enumerate **real KLRAMS layers**, mapped to real tables. Do not invent fictional tables.

| Layer key (KLLayers / UI) | Label | PostgreSQL table | Notes |
| ------------------------- | ----- | ---------------- | ----- |
| `roadnet` | Road network | `roads` | Flat typed columns from shapefile; quoted mixed-case names (`Section_La`, `Rd_End_cha`, …); `geom` |
| `roadnet2` | Full / merged road network | `full_road_network` | Scalar cols + free-form `props jsonb` + `geom` |
| `condition` / `pci-avg` / `pci-worst` | Condition / PCI | `condition_segments` | Built/materialized from `condition`; treat as derived — warn before ALTER |
| `iri2km` | Avg IRI (2 km) | `iri_2km_segments` | Rebuilt by `IriSegmentService` (`DROP`/`CREATE AS`); **schema edits are unsafe** — display read-only, block destructive DDL |
| Asset keys (`bridge`, `culvert`, `fwd`, …) | Road assets | `road_assets` | Shared table filtered by `asset_type`; free-form `attrs jsonb` |
| `traffic` | Traffic stations | `traffic_stations` | Small LRS layer; GeoJSON OK |
| `video-catalog` | Video Catalogue | `road_video` | No PostGIS geometry — `section_label` links each row to a video file on disk (`/videos/**`); Feature Type/CRS show as `—` |
| `district` / `constituency` | Boundaries | `boundary` | Stored as `type` + `geojson text` (not row-per-feature PostGIS) — show as special case, not a normal attribute table |
| Tool layers (`selection`, `measure`) | Ephemeral UI | — | **Exclude** from Layer Management (no DB table) |

For assets, one Layer Management row per asset type, but **one physical table**. Current Attributes = columns of `road_assets` (plus optional jsonb key discovery — see below).

## Module structure (final UX)

**Layer Management**

### Current Layers

- List all existing layers from the map above (driven by a small backend registry + `KLLayers` keys)
- Actions: View · Edit · Configure · Style · Zoom · Delete *(Delete = soft/hide or remove **user-imported** layers only; never drop core tables like `roads`)*

### Layer Details

- Basic info (key, label, group, geometry family)
- Database information (schema, table name, primary key)
- CRS (from `geometry_columns` / `Find_SRID` — KLRAMS uses EPSG:4326)
- Geometry type (`ST_GeometryType` sample or `geometry_columns.type`)
- Feature count (`SELECT count(*) …` with asset_type / period filters when needed)

### Current Attributes / Existing Schema  ← **required**

- Live columns from PostgreSQL/PostGIS
- Read-only by default
- **Edit Attributes** unlocks mutations

### Attribute Management

- Add / Edit / Delete column
- Validate + confirm before DDL

### Configuration

- Visibility, query, search, editing, import, export, layer order  
  (wire to existing toggles / `KLLayers` / console flags — do not duplicate a second visibility system)

### Style

- Point / line / polygon style hooks matching existing MapLibre paint patterns

# Current Layer Attributes / Schema

## Requirement

For every existing layer, **automatically read the actual attribute schema from PostgreSQL/PostGIS** and display it.

- Do **NOT** use hard-coded or sample attributes.
- Do **NOT** recreate the table.
- Do **NOT** drop/recreate columns to “refresh” the UI.
- Do **NOT** overwrite existing values with sample values.
- Do **NOT** auto-convert data types.

When the user selects an existing layer, show a **Current Attributes** table of columns that actually exist on that layer’s table.

### Required table columns

| Column Name | Current Data Type | Precision | Scale | String Length | Date Format | Sample Value | Nullable | Default Value |
| ----------- | ----------------- | --------: | ----: | ------------: | ----------- | ------------ | -------- | ------------- |

### 1. Column Name

Display the **actual** database column name (preserve case). Examples from KLRAMS: `Section_La`, `Road_Name`, `Measrd_Ln`, `attrs`, `geom`.

Never silently rename.

### 2. Current Data Type

Map PostgreSQL/`information_schema.data_type` (+ `udt_name` when needed) to a friendly label:

| PostgreSQL | Display |
| ---------- | ------- |
| `smallint`, `integer` | Integer |
| `bigint` | Big Integer |
| `numeric`, `decimal` | Decimal |
| `real`, `double precision` | Decimal *(or “Float” if you want a distinct label — pick one and stay consistent)* |
| `character varying`, `character`, `text` | Text |
| `boolean` | Boolean |
| `date` | Date |
| `timestamp without time zone`, `timestamp with time zone` | DateTime |
| `jsonb`, `json` | JSON |
| `USER-DEFINED` / `geometry` | Geometry |

### 3–5. Precision / Scale / String Length

Read from `information_schema.columns`:

- `numeric_precision`, `numeric_scale`
- `character_maximum_length` → number, or **Unlimited** when null on `text`
- Non-applicable cells → `—`

### 6. Date Format

KLRAMS has **no global `app.date-format` property today**. Use application display conventions:

- Date → `YYYY-MM-DD`
- DateTime → `YYYY-MM-DD HH:mm:ss`

If a per-column display format is later stored in layer metadata, prefer that. Non-date → `—`.

### 7. Sample Value

Real data only. Backend equivalent of:

```sql
SELECT "<col>" FROM <table> WHERE "<col>" IS NOT NULL LIMIT 1
```

Rules:

- Quote identifiers (`"Section_La"`) — many `roads` columns are mixed-case.
- Allow-list table from the layer registry; allow-list column from `information_schema` + `SAFE_NAME` (or quote-safe check rejecting `"`).
- Never expose raw SQL to the frontend.
- All-null column → `No value`.
- Geometry → `ST_GeometryType(geom)` stripped to `Point` / `LineString` / `MultiLineString` / `Polygon` — **never** dump WKT/WKB.
- `jsonb` → short preview (e.g. truncated compact JSON, max ~120 chars), not a full attrs blob.

### 8. Nullable

From `is_nullable` → `Yes` / `No`.

### 9. Default Value

From `column_default`. None → `—`. Show the expression as stored (e.g. `nextval(...)`, `false`) without evaluating it as user data.

## JSONB / free-form attributes (KLRAMS-specific)

Some layers store extra fields inside jsonb, not as typed columns:

| Table | JSONB column | How to show |
| ----- | ------------ | ----------- |
| `road_assets` | `attrs` | One row for column `attrs` (type JSON). Optional second section: **Discovered keys in attrs** (distinct keys from a capped sample of rows) — display-only, **not** ALTER targets |
| `full_road_network` | `props` | Same pattern |
| `iri_2km_segments` | `lane_avgs` | Same pattern |

Do **not** pretend jsonb keys are PostgreSQL columns. Do **not** offer “Delete Column” on a jsonb key unless you implement a separate, explicit jsonb-key editor (out of scope for v1).

Flattening for map click (`props_json` / `attrs_json` in MVT) stays as today — Layer Management must not break tile property contracts.

## Backend API (suggested)

All under `/api/layers/...`, authenticated.

```
GET  /api/layers
GET  /api/layers/{layerKey}
GET  /api/layers/{layerKey}/attributes          # Current Attributes (+ samples)
POST /api/layers/{layerKey}/attributes          # Add column (confirm token / flag)
PATCH /api/layers/{layerKey}/attributes/{col}   # Alter definition
DELETE /api/layers/{layerKey}/attributes/{col}  # Drop column
```

### Attributes response shape (illustrative)

```json
{
  "layerKey": "roadnet",
  "table": "roads",
  "readOnlyReason": null,
  "columns": [
    {
      "name": "Road_Name",
      "pgType": "character varying",
      "displayType": "Text",
      "precision": null,
      "scale": null,
      "stringLength": 150,
      "dateFormat": null,
      "sampleValue": "MC Road",
      "nullable": true,
      "defaultValue": null
    },
    {
      "name": "geom",
      "pgType": "USER-DEFINED",
      "displayType": "Geometry",
      "precision": null,
      "scale": null,
      "stringLength": null,
      "dateFormat": null,
      "sampleValue": "MultiLineString",
      "nullable": false,
      "defaultValue": null,
      "protected": true
    }
  ],
  "jsonbKeys": []
}
```

Implementation sketch:

- Generalize the `RoadColumns` / `RoadUploadController` catalogue query to a shared `LayerSchemaService`.
- Join/filter `information_schema.columns` for the mapped table.
- For geometry sample use `ST_GeometryType`.
- Mark protected columns: `id`, `geom`, PK/serial, `period_id` (where system-managed), rebuild-only tables.

### Read-only layers

Set `readOnlyReason` and reject DDL for:

- `iri_2km_segments` (rebuild drops table)
- `condition_segments` if rebuilt from raw `condition` (same class of risk)
- `boundary` (not a normal attribute table)
- Ephemeral / missing table mapping

## Attribute Management (mutations)

Current Attributes is **read-only by default**. Provide **Edit Attributes**.

When editing, allow (only on mutable tables):

- Add New Column
- Edit Column Definition
- Delete Column
- Change Description *(store in a side metadata table if PG comments are not enough — optional v1.1)*
- Set Default Value / Nullable / Length / Precision / Scale / Date Format (display meta)

### Before any DDL

1. Confirmation dialog naming the **table** and **column**
2. Warn if existing data can be affected (type change, drop, set NOT NULL)
3. Validate type + constraints on **frontend and backend**
4. Reject unsafe casts when existing values cannot convert (`USING` check query first)
5. Never silently delete data
6. Never `DROP TABLE` / recreate as part of “edit column”

### Add Column — dynamic fields by type

| Type | Show |
| ---- | ---- |
| Text | String Length, Default, Nullable, Description |
| Integer / Big Integer | Default, Nullable, Description |
| Decimal | Precision, Scale, Default, Nullable, Description |
| Date / DateTime | Date Format (display), Default, Nullable, Description |
| Boolean | Default, Nullable, Description |
| Geometry | **Blocked** in normal editor — geometry is owned by GIS upload / LRS pipelines |
| JSON | Optional for advanced admin only; default **blocked** on core layers |

### Validation rules

- Precision/Scale only for Decimal; Scale ≤ Precision
- String Length only for Text (varchar); omit / Unlimited → `text`
- Date Format only for Date/DateTime
- Integer defaults must be integers
- NOT NULL rejected if nulls exist
- Column names: PostgreSQL rules + `SAFE_NAME` (or documented exception for quoted legacy names on **rename only** — prefer no rename of legacy shapefile columns)
- Duplicate names rejected (case-sensitive as stored)
- Reserved / protected names rejected (`id`, `geom`, …)

### After successful DDL

- Refresh catalogue caches (`RoadColumns` and any new `LayerColumns` cache — today process-lifetime; either restart note or add explicit `invalidate()`)
- Refresh GeoJSON caches where applicable (`/geojson/refresh` patterns)
- Log the change (reuse `upload_log` or a small `schema_change_log`)

## Implementation phases

### Administrative Boundary (Folder → Layer)

Structure:

```
Folder name
  └── Layer name
  └── Layer name
```

Seeded:

```
Administrative Boundary
  ├── District boundary
  └── Constituency boundary
```

APIs: `GET/POST /api/layers/folders`, `POST /api/layers/folders/{folderKey}/layers`, `GET /api/layers/layer-options` (feature type / format choices for the create-layer form).
Creating a layer under a folder adds its Import option in Data Console → Boundaries.
Import prompts Replace vs Add when data already exists.

---

### Phase 1 — Discover only (ship first) ✅ implemented

Implemented as:

- Backend: `LayerCatalog`, `LayerSchemaService`, `LayerController` (`GET /api/layers`, `/{key}`, `/{key}/attributes`)
- UI: `/layers.html` (linked from `home.html`)
- Read-only; no DDL endpoints

### Phase 1.5 — Three-group taxonomy + layer metadata ✅ implemented

- System Generated / Protected Layers / Administrative Boundary & Custom Layers sections (see "Layer taxonomy" above)
- `admin_boundary_layers.feature_type` / `.import_format` / `.srid` columns, populated on create for `boundary`-kind layers
- `layers.html` redesigned into the three-section layout with modal create-folder/create-layer forms

Checklist:

1. Layer list + details + feature count + CRS/geom type  
2. **Current Attributes** fully database-driven (including real sample values)  
3. Read-only UI; Edit button hidden or disabled with “coming next”  
4. Zero DDL against production tables  

### Phase 2 — Safe mutations

1. Add column  
2. Alter nullable / default / varchar length (widen only by default)  
3. Drop column (extra confirm)  
4. Type changes only with conversion probe  

### Phase 3 — Configure / Style polish

Wire visibility, order, and style editors to existing MapLibre layers without a second source of truth.

## Acceptance checks

- [ ] Selecting Road network shows columns that match `\d roads` / `information_schema` — not a canned list  
- [ ] Sample values are real non-null DB values (or `No value`)  
- [ ] Geometry samples show type names, not coordinates  
- [ ] `road_assets` shows `attrs` as JSON; jsonb keys are not fake columns  
- [ ] `iri_2km` attributes are visible but DDL is blocked  
- [ ] No table drop/recreate occurs when opening Current Attributes  
- [ ] SQL injection impossible via layerKey/columnName (allow-list + safe identifiers)  
- [ ] MVT layers still paint after Phase 1 (no regression)  
- [ ] After Phase 2 add-column on `roads`, `RoadColumns` / colour-by-attribute sees the new field after cache invalidate

## Explicit non-goals (v1)

- Replacing MapLibre or PostGIS  
- Auto-migrating shapefile schemas on every import beyond what `RoadUploadController` already does (widen overflow varchar → text)  
- Editing jsonb keys as if they were columns  
- Adding arbitrary geometry columns through the attribute editor  
- Managing ephemeral tool layers (`sel-road`, measure)  
- Recreating iRoads-style layer admin disconnected from KLRAMS tables  

---

## Final reminder

**Existing layer → Existing table → Existing columns → Existing data** must remain unchanged until the administrator confirms a validated schema change. Current Attributes is primarily for **discovering and managing the actual existing schema** inside KLRAMS.
